# External audit of Phase 0, S01 and S02 — findings (2026-10-28, read-only audit of main at 28f0fdc)

An external model audited `main` (tree identical to PR #32's head) across security, database, backend, front ends, UI/UX, offline, tests, docs and tooling, without changing anything. Claude verified every finding against the code before fixing it; all twelve were confirmed. Fixes on `fix/S02-audit`, each with a test that fails without it.

## High
- SEC-01 `apps/restaurant/electron/device-service.ts` — `lock()` ran in the main process's serial queue, so "Switch cashier" waited behind a member-list or token refresh on a slow connection and the previous member's session stayed open (rule 32).
  - Status: **Fixed**: the session ends at once, outside the queue; ending it on the server follows in turn; a token refresh that finishes after the lock ends the rotated session instead of reopening it (`device-service.test.ts`).
- SEC-02 `apps/api/src/modules/platform/identity/tickets.ts` — an unused sign-in ticket issued before a password reset stayed valid for its 10 minutes and could register a new PC (rule 14).
  - Status: **Fixed**: a ticket carries a keyed hash of the password it rests on, checked when verified and, sharing the account row, when used, as the console's step tickets do (`identity.test.ts`).
- BE-01 `apps/api/src/modules/platform/identity/platform-users.service.ts` — a console reset locked only its target, so two admins resetting each other could leave no active admin (rule 42).
  - Status: **Fixed**: a reset locks the admins first, refuses the last active admin (`LAST_ADMIN`) and rechecks the operator under those locks; disable and demotion recheck the operator too; the CLI still recovers the last admin (`console-identity.test.ts`).
- FE-01 `apps/restaurant/src/features/sign-in/sign-in-flow.tsx` — no screen requested a `password_reset` code, so an authorized reset could not be completed (rule 14).
  - Status: **Fixed**: "Forgot your password?" on the sign-in screen asks for the code with `password_reset`, then the OTP and new-password steps (E2E in `device.spec.ts`, RTL screenshot `personal-password-reset`).

## Medium
- BE-02 `apps/api/src/modules/platform/tenancy/tenancy.service.ts` — archiving a branch did not check members whose only branch it was (edge case 6).
  - Status: **Fixed**: refused with the new code `BRANCH_HAS_MEMBERS` through access's `TENANT_MEMBERS` port, under the tenant row lock that staff writes also take (`identity.test.ts`).
- BE-03 `apps/api/src/modules/platform/access/staff.service.ts` — `writableAt` read the time before waiting for the tenant's share lock (the S01 A02 mistake in a new place).
  - Status: **Fixed**: the time is read after the lock; barrier test in `tenancy.test.ts`.
- BE-04 `apps/api/src/modules/platform/identity/auth.service.ts` — a recognized personal device moved its expiry 90 days on in the database, but its cookie kept the first 90 days.
  - Status: **Fixed**: the sign-in that recognizes it sets the cookie again (`identity.test.ts`).
- FE-02 `apps/restaurant/src/features/session/` — a PC kept `/me` across sessions, and an offline PIN session could use a cached `/me` instead of the member list.
  - Status: **Fixed**: a PC forgets `/me` between sessions; an offline session takes its access from the member list only.
- FE-03 `apps/restaurant/vite.config.ts` — the dev server had no `/api` proxy, so the browser's personal-session cookie could not work against the local API.
  - Status: **Fixed**: `/api` forwarded to the local API, as the console's dev server does; documented in `apps/restaurant/CLAUDE.md`.
- OFF-01 `apps/restaurant/electron/device-service.ts` — `status()` read the clock without keeping it, so a clock set back after an expired window reopened it (rule 31).
  - Status: **Fixed**: every look at the clock (status, an offline refresh) raises the highest time seen, and no save lowers it except a confirmed member list (`device-service.test.ts`).
- TEST-01 `apps/api/test/architecture/architecture.test.ts` — ADR 0025's platform → food boundary is checked in the API only, not in `packages/contracts` and `packages/db`; `contracts/tenancy.ts` imports `orders.ts` and the `branch_charges` check lists the food order types.
  - Status: **Fixed** on `refactor/sales-channels` (owner, 2026-10-28: "do the best"): the charges stay in platform tenancy as the architecture places them, on generic **sales channels** (`salesChannelSchema` in `contracts/tenancy.ts`; the food `orders.ts` is gone until S09); the architecture test gives every file of `packages/contracts/src` and `packages/db/src/schema` a layer and refuses a platform → food import (ADR 0025 amendment). Stored values and the column name are unchanged: no migration.
- TOOL-01 `.claude/settings.json` — the git guard ran for Bash only, though PowerShell is allowed too.
  - Status: **Fixed**: registered for `Bash|PowerShell`; a test checks every allowed shell tool has it (`packages/config/test/git-guard.test.ts`).
