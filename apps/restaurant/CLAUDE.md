# apps/restaurant

Vertex Food Restaurant, the offline-first Windows app (ADR 0008, 0022, 0023, layout ADR 0020): a React + Vite + TanStack Router renderer in an Electron shell, Arabic-first RTL (ADR 0018). Copied from Vertex Shifa's clinic skeleton and adapted. Today it has the shell and S01's online-only setup screens: no local database, sync client, branch hub, printing, preload API or packaging yet (S04, S10 and S11 bring them).

## Layout
- `src/main.tsx` mounts i18n, the `DirectionProvider` and the router; `src/routes/` holds thin file-based routes (TanStack Router; `src/routeTree.gen.ts` is generated by the Vite plugin on `dev` and `build`, committed, never edited or read); `__root.tsx` sets the shell and the error and not-found states.
- `src/features/<area>/`: the components, queries and forms of one area. The pattern to copy for an online-only screen is S01's: `features/tenancy/` (`queries.ts` with `queryOptions`, the API calls and `useSetupCache`; pure drafts and checks with unit tests in `branch-draft.ts`; shared fields), `features/settings/` (a form per section: `useDraft`, `useSettingsSave`, `SaveActions`, the `updatedAt` it started from kept as its base), `features/setup/` (the wizard). `tenant-gate.tsx` wraps every route (`__root.tsx`): tenant loaded first, onboarding redirects, status banner, offline notice. App-wide `src/components/` (shell, state card, `QueryStates`, `OfflineNotice`, `FieldGroup`) and `src/lib/`: `i18n.ts`; `error-logging.ts` (errors logged by name only); `api.ts` (`openapi-fetch` client typed by `api-schema.gen.ts`, `unwrap` to `ApiError` with the code only); `query-client.ts` (nothing paused or queued offline, `fetchNow`); `online.ts`; `error-text.ts` (the Arabic text of a code); `format.ts`; `staff-access.ts` (`useStaffAccess`, `can`: the owner's access until S02 provides the session's).
- The UI comes from `packages/ui` (ADR 0018): `src/styles.css` imports Tailwind, `fonts-desktop.css` and the design system's styles; `vite.config.ts` adds `vertexFoodWeb()` (`theme-init.js` before the first paint, the first screen's fonts preloaded, both served from `'self'` under the CSP). The shell (`components/app-shell.tsx`) is `AppLayout`: the sidebar with the links of `features/tenancy/restaurant-nav.tsx` (none while the tenant loads, in the wizard or "setup in progress"), the `ThemeToggle` and `PoweredBy`; `index.html` takes the favicon from `brand/`.
- `electron/main.ts`: the main process. One window (`electron/window-options.ts`: shrinks to 360 × 480, so the phone layout applies to a narrow window too) with `contextIsolation`, `sandbox`, no `nodeIntegration` and no preload; new windows, webviews and navigation outside the renderer's origin refused; every permission denied; one instance only. The built renderer is served from `app://restaurant/` (`electron/app-protocol.ts`: path containment, client routes get `index.html`, a strict CSP header). `--dev-server=<url>` loads the Vite dev server, only when unpackaged and only on loopback HTTP (`electron/navigation.ts`). The local database, the sync client, the hub server (ADR 0022) and printing (ADR 0023) join the main process here.
- `hub-clients/` (kitchen display, waiter app, ADR 0008): the web clients the hub serves over the LAN, from S04, S11 and S12.
- `src/lib/api-schema.gen.ts` is generated from `apps/api/openapi.json` by `test/api-schema.test.ts`; after an API change run `pnpm --filter @vertex-food/restaurant exec vitest run test/api-schema.test.ts -u`. Never edit or read it.
- Configuration, read at build by Vite: `VITE_API_URL` (the API's URL; unset, requests go to the renderer's own origin, which only the E2E uses). The build writes its origin (`connectOrigins` in `electron/app-protocol.ts`: HTTPS or loopback HTTP only) to `dist/renderer/connect-origins.json`, which the main process and `vite preview` read for `connect-src`, so the policy always names the API the renderer was built with.
- Unit tests sit next to the code; the logical-CSS and token rules are `packages/ui`'s convention test, which covers `src/`. `e2e/`: Playwright against `vite preview` (Chromium, Electron's engine), light and dark, with Electron's CSP header (`vite.config.ts` reads it from `electron/app-protocol.ts`); any CSP violation fails the test (`failOnCspViolation`). `e2e/mock-api.ts` answers the API's routes in memory with the contracts' schemas and rules (stale `updatedAt`, suspended and closed writes, a due scheduled change through `effectiveStatusState` at its `clock`, which a `page.clock` test points at the page's, completeness) until S02 makes a real stack testable; synthetic data only.
- Ports: dev 5273, `vite preview` 4273 (console 5274/4274, web 5275/4275), so every E2E server runs side by side; the range differs from Vertex Shifa's (51xx/41xx) so both projects run on one PC.

## Rules
- Every text through i18next with keys from `packages/i18n` (`useTranslation('<namespace>')`; this app's namespace is `restaurant`); never a literal in a component. Numbers and dates through `Intl` with `formatLocale` from `@vertex-food/i18n` (Syrian month names, Latin digits); times shown in `displayTimeZone` (`Asia/Damascus`).
- Design-system components and tokens only (`packages/ui`): semantic utilities (`bg-surface`, `text-muted-foreground`), never a color value, logical directions only (`ms-`, `ps-`, `start-`, `text-start`): pinned by `packages/ui/src/conventions.test.ts`. The window title comes from i18n too (`document.title`).
- Every screen has its loading, empty, error and offline states (ADR 0020); once sync exists, the sync status and last sync time are always visible (ADR 0008). An error state never shows or logs the error's message: it may carry customer data (ADR 0016). `main.tsx` routes React's and the router's error hooks to `logErrorLabel` and redacts any `Error` passed to `console.error`/`console.warn`; log errors with `logErrorLabel`, never the error object or its message.
- The renderer is untrusted: it gets no Node access. The local database, sync and the hub live in the main process; the renderer reaches them only through a narrow IPC API in a preload, added with S04. Never loosen `contextIsolation`, `sandbox` or the CSP; a new origin (API, sync service) is added to `connect-src` explicitly.
- Data comes from the local database and changes go through sync commands sent to the active hub (ADR 0008, 0022). Configuration screens (S01) are online only: they call the API through `src/lib/api.ts` and TanStack Query, never queue a change, and while offline keep the last loaded values read-only (`OfflineNotice`) or show `OfflineState`. Every edit sends the `updatedAt` it started from; a `CONFLICT` reloads the record and says so.
- `main.tsx` mounts `CSPProvider disableStyleElements`: Base UI may not inject `<style>` under the CSP; the rules it would inject live in `packages/ui`'s `base.css`.
- "Powered by Vertex Food" (`PoweredBy`) is always visible (ADR 0018). The restaurant's accent (`tenantStyle`, `bg-tenant-accent`) arrives with branding (S08); the rest keeps the Vertex identity (ADR 0010).
- UI changes add or update the E2E RTL screenshots (light and dark) and are looked at before the PR. Every screen is in `e2e/responsive.spec.ts` at the `viewports` of `e2e/screenshot.ts` (phone, tablet both ways, desktop), with `expectNoHorizontalOverflow`.

Run: `pnpm --filter @vertex-food/restaurant test` · E2E: `pnpm verify apps/restaurant/e2e/<file>.spec.ts` (builds first; every suite runs in CI, `docs/testing.md`) · dev: `pnpm --filter @vertex-food/restaurant dev` (browser) and `pnpm --filter @vertex-food/restaurant dev:electron` (Electron on the dev server) · built app: `pnpm --filter @vertex-food/restaurant start`.
