# apps/restaurant

Vertex Food Restaurant, the offline-first Windows app (ADR 0008, 0022, 0023, layout ADR 0020): a React + Vite + TanStack Router renderer in an Electron shell, Arabic-first RTL (ADR 0018). Copied from Vertex Shifa's clinic skeleton and adapted. Today it is the shell only: no local database, sync client, branch hub, printing, preload API or packaging yet (S04, S10 and S11 bring them).

## Layout
- `src/main.tsx` mounts the router and i18n; `src/routes/` holds thin file-based routes (TanStack Router; `src/routeTree.gen.ts` is generated by the Vite plugin on `dev` and `build`, committed, never edited or read); `__root.tsx` sets the shell and the error and not-found states.
- `src/features/<area>/`: the components, queries and forms of one area; the pattern to copy is `features/home/`. App-wide `src/components/` (shell, states) and `src/lib/` (`i18n.ts`; `error-logging.ts`: errors logged by name only).
- `src/styles.css`: local colors (light and dark) and spacing until the brand phase replaces them with `packages/tokens` and `packages/ui`.
- `electron/main.ts`: the main process. One window with `contextIsolation`, `sandbox`, no `nodeIntegration` and no preload; new windows, webviews and navigation outside the renderer's origin refused; every permission denied; one instance only. The built renderer is served from `app://restaurant/` (`electron/app-protocol.ts`: path containment, client routes get `index.html`, a strict CSP header). `--dev-server=<url>` loads the Vite dev server, only when unpackaged and only on loopback HTTP (`electron/navigation.ts`). The local database, the sync client, the hub server (ADR 0022) and printing (ADR 0023) join the main process here.
- `hub-clients/` (kitchen display, waiter app, ADR 0008): the web clients the hub serves over the LAN, from S04, S11 and S12.
- `test/`: source tests (`logical-css.test.ts`). Unit tests sit next to the code. `e2e/`: Playwright against `vite preview` (Chromium, Electron's engine), light and dark.
- Ports: dev 5273, `vite preview` 4273 (console 5274/4274, web 5275/4275), so every E2E server runs side by side; the range differs from Vertex Shifa's (51xx/41xx) so both projects run on one PC.

## Rules
- Every text through i18next with keys from `packages/i18n` (`useTranslation('<namespace>')`; this app's namespace is `restaurant`); never a literal in a component. Numbers and dates through `Intl` with `formatLocale` from `@vertex-food/i18n` (Latin digits); times shown in `displayTimeZone` (`Asia/Damascus`).
- Logical CSS only (`margin-inline-*`, `inset-inline-*`, `inline-size`, `text-align: start`…), no physical 3- or 4-value shorthands, no `translateX`: pinned by `test/logical-css.test.ts`, whose samples prove each rule still matches. The window title comes from i18n too (`document.title`).
- Every screen has its loading, empty, error and offline states (ADR 0020); once sync exists, the sync status and last sync time are always visible (ADR 0008). An error state never shows or logs the error's message: it may carry customer data (ADR 0016). `main.tsx` routes React's and the router's error hooks to `logErrorLabel` and redacts any `Error` passed to `console.error`/`console.warn`; log errors with `logErrorLabel`, never the error object or its message.
- The renderer is untrusted: it gets no Node access. The local database, sync and the hub live in the main process; the renderer reaches them only through a narrow IPC API in a preload, added with S04. Never loosen `contextIsolation`, `sandbox` or the CSP; a new origin (API, sync service) is added to `connect-src` explicitly.
- Data comes from the local database and changes go through sync commands sent to the active hub (ADR 0008, 0022); TanStack Query arrives with the first online-only screen.
- "Powered by Vertex Food" is always visible (ADR 0018).
- UI changes add or update the E2E RTL screenshots (light and dark) and are looked at before the PR.

Run: `pnpm --filter @vertex-food/restaurant test` · E2E (after `build`): `pnpm --filter @vertex-food/restaurant test:e2e` · dev: `pnpm --filter @vertex-food/restaurant dev` (browser) and `pnpm --filter @vertex-food/restaurant dev:electron` (Electron on the dev server) · built app: `pnpm --filter @vertex-food/restaurant start`.
