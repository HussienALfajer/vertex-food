# apps/customer

The Vertex Food customer app for Android and iOS (ADR 0003, layout ADR 0020): React Native + Expo (SDK 58, managed workflow) with Expo Router, Arabic-first RTL (ADR 0018). Copied from Vertex Shifa's patient skeleton and adapted. Today it is the shell only: no API calls, sign-in, secure storage, read cache or push yet (S16, S17). The customer's web ordering is `apps/web`, not an Expo web export.

## Layout
- `app.config.ts`: the app name from the catalog, RTL forced natively (`extra.forcesRTL`, read by `expo-localization`), the sitemap route off. Store identifiers, the EAS project and icons arrive with the first store build (Q3). `android/` and `ios/` are generated by prebuild and git-ignored.
- `src/app/`: thin Expo Router routes. `_layout.tsx` runs the start-up (redacted console and native error reports, `forceRightToLeft`), sets the providers and the shell and exports the `ErrorBoundary`; `index.tsx` re-exports a feature's screen; `+not-found.tsx` is the not-found state.
- `src/features/<area>/`: the screens, queries and forms of one area; the pattern to copy is `features/home/`. App-wide `src/components/` (shell, state card, states) and `src/lib/` (`i18n.ts`; `error-logging.ts`: errors logged by name only; `native-error-reports.ts`; `rtl.ts`; `theme.tsx`: local colors light and dark and spacing).
- `test/`: source tests (`logical-styles.test.ts`). Unit tests sit next to the code and import no React Native runtime (Vitest runs in Node).
- `pnpm build` is `expo export` for Android and iOS (the JavaScript bundles, into `dist/`), which proves the app bundles; native builds run on EAS Build (ADR 0003). Dev server: 5276.

## Rules
- Every text through i18next with keys from `packages/i18n` (`useTranslation('<namespace>')`; this app's namespace is `customer`); never a literal in a component. Numbers and dates through `Intl` with `formatLocale` from `@vertex-food/i18n` (Latin digits); times shown in `Asia/Damascus`.
- Logical style properties only (`marginInlineStart`, `paddingBlock`, `insetInlineEnd`, `textAlign: 'auto'`, `flexDirection: 'row'`, which follows the direction), no `Left`/`Right`/`Top`/`Bottom` properties, `Horizontal`/`Vertical` shorthands or `translateX`: pinned by `test/logical-styles.test.ts`, whose samples prove each rule still matches.
- Colors through `useColors()` from `lib/theme.tsx`, never a literal in a component; it gives way to `packages/tokens` and `packages/ui-native` at the brand phase (ADR 0018). System fonts only.
- Every screen has its loading, empty, error and offline states (ADR 0020). An error state never shows or logs the error's message: it may carry customer data (ADR 0016). Log errors with `logErrorLabel`, never the error object or its message; no crash reporter receives a message.
- Not offline-first: a read cache of recent orders and addresses; ordering needs a connection (ADR 0003). Totals shown are recomputed by the API (ADR 0007). Validation through `packages/contracts`.
- Push is Expo notifications plus the native token, tested on development builds, never Expo Go (ADR 0003). `google-services.json` and service-account keys never enter the repository.
- Versions of Expo packages come from `pnpm exec expo install <package>`, which matches the SDK; pin them exactly.
- No RTL screenshot yet: the app has no web export. Screens are checked on a development build until the design system brings a screenshot path (`TASKS.md`).

Run: `pnpm --filter @vertex-food/customer test` · build: `pnpm --filter @vertex-food/customer build` · dev: `pnpm --filter @vertex-food/customer dev`.
