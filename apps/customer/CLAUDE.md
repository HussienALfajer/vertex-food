# apps/customer

The Vertex Food customer app for Android and iOS (ADR 0003, layout ADR 0020): React Native + Expo (SDK 58, managed workflow) with Expo Router, Arabic-first RTL (ADR 0018). Copied from Vertex Shifa's patient skeleton and adapted. Today it is the shell only: no API calls, sign-in, secure storage, read cache or push yet (S16, S17). The customer's web ordering is `apps/web`; the Expo web export exists only for the E2E screenshots and is never hosted (owner, 2026-10-19).

## Layout
- `app.config.ts`: the app name from the catalog, Android, iOS and web (the static web export, for the E2E only), RTL forced natively (`extra.forcesRTL`, read by `expo-localization`), the sitemap route off. Store identifiers, the EAS project and icons arrive with the first store build (Q3); the icon is `brand/logo/png/app-icon-1024.png`. `android/` and `ios/` are generated by prebuild and git-ignored.
- `src/app/`: thin Expo Router routes. `_layout.tsx` runs the start-up (redacted console and native error reports, `forceRightToLeft`), sets the providers and the shell and exports the `ErrorBoundary`; `index.tsx` re-exports a feature's screen; `+not-found.tsx` is the not-found state; `+html.tsx` is the document of the web export (Expo SDK 58: it places `useServerDocumentContext()`'s head and body nodes, or the bundle never loads).
- `src/features/<area>/`: the screens, queries and forms of one area; the pattern to copy is `features/home/`. App-wide `src/components/` (shell, state card, states) and `src/lib/` (`i18n.ts`; `error-logging.ts`: errors logged by name only; `native-error-reports.ts`; `rtl.ts`). The theme comes from `@vertex-food/ui-native` (`ThemeProvider` in `_layout.tsx`, the device's choice kept in AsyncStorage; the shell has the mark, `ThemeToggle` and `PoweredBy`, the status bar following the theme drawn).
- Unit tests sit next to the code and import no React Native runtime (Vitest runs in Node); the logical-style and color rules are `packages/ui-native`'s convention test, which covers `src/`. `e2e/`: Playwright against the web export at a phone's size, light and dark, served by `e2e/web-server.ts` on port 4276.
- `pnpm build` is `expo export` for Android, iOS and web (the JavaScript bundles and the static web export, into `dist/`), which proves the app bundles; native builds run on EAS Build (ADR 0003). Dev server: 5276.

## Rules
- Every text through i18next with keys from `packages/i18n` (`useTranslation('<namespace>')`; this app's namespace is `customer`); never a literal in a component. Numbers and dates through `Intl` with `formatLocale` from `@vertex-food/i18n` (Latin digits); times shown in `Asia/Damascus`.
- Logical style properties only (`marginInlineStart`, `paddingBlock`, `insetInlineEnd`, `textAlign: 'auto'`, `flexDirection: 'row'`, which follows the direction), no `Left`/`Right`/`Top`/`Bottom` properties, `Horizontal`/`Vertical` shorthands or `translateX`: pinned by `packages/ui-native/test/conventions.test.ts`.
- Colors, spacing, radii and type sizes through `useTheme()` from `@vertex-food/ui-native` (the Vertex tokens, ADR 0018), never a literal in a component; `Button` and `Card` from there too. System fonts only (owner, 2026-10-19). The app's frame keeps the Vertex identity; a restaurant's accent shows only on its page (ADR 0010, S17).
- Every screen has its loading, empty, error and offline states (ADR 0020). An error state never shows or logs the error's message: it may carry customer data (ADR 0016). Log errors with `logErrorLabel`, never the error object or its message; no crash reporter receives a message.
- Not offline-first: a read cache of recent orders and addresses; ordering needs a connection (ADR 0003). Totals shown are recomputed by the API (ADR 0007). Validation through `packages/contracts`.
- Push is Expo notifications plus the native token, tested on development builds, never Expo Go (ADR 0003). `google-services.json` and service-account keys never enter the repository.
- Versions of Expo packages come from `pnpm exec expo install <package>`, which matches the SDK; pin them exactly.
- UI changes add or update the E2E RTL screenshots (light and dark) and are looked at before the PR; native-only behaviour (status bar, safe areas, forced RTL on a device) is still checked on a development build.

Run: `pnpm --filter @vertex-food/customer test` · build: `pnpm --filter @vertex-food/customer build` · E2E (after `build`): `pnpm --filter @vertex-food/customer test:e2e` · dev: `pnpm --filter @vertex-food/customer dev`.
