# apps/console

The Vertex staff console (ADR 0002, layout ADR 0020): a React + Vite + TanStack Router app, browser only, Arabic-first RTL (ADR 0018). Copied from Vertex Shifa's console and adapted. Today it holds the console identity of S02 (spec S02 rules 38–43, screens 14–17): sign-in with the password and a TOTP or a recovery code, the setup of a new or reset user (setup code, password, authenticator QR, recovery codes shown once), the re-authentication dialog, platform users and my account. S20 brings the dispatch board; S22 restaurants, agreements, entitlements, owner recovery and support access.

## Layout
- `src/main.tsx` mounts i18n, the `DirectionProvider`, TanStack Query, the `Toaster` and the router, and wires the end of the session into the API client (`startSession`); `src/routes/` holds thin file-based routes (TanStack Router; `src/routeTree.gen.ts` is generated by the Vite plugin on `dev` and `build`, committed, never edited or read); `__root.tsx` sets the session gate and the error and not-found states.
- `src/features/<area>/`: the components, queries and forms of one area. `features/session/` (S02): `session.ts` (`meQuery`, `signedIn` and `forgetSession`, `signOut`, `startSession`, `needsReauth`, `holds`), `session-gate.tsx` (every screen but `/sign-in` needs a session; the shell with the sidebar's links and the user's name and sign-out), `sign-in-api.ts` and `sign-in-screen.tsx` (screen 14; the steps' tickets stay in the screen's memory; the proof of work is `solveProofOfWork` from contracts), `reauth.tsx` (screen 15: `ReauthProvider` and `useReauth`), `password-hints.tsx`, `qr-code.tsx` (the TOTP QR, drawn with `uqr`, dark on white in both themes). `features/platform-users/` (screen 16: `queries.ts`, `access-draft.ts` with its unit test: the role and adjustments as the dialog edits them, sent only within the console limits; the screen with its dialogs) and `features/account/` (screen 17). The pattern to copy for a screen is `features/platform-users/`.
- App-wide `src/components/` (`app-shell.tsx`: `AppLayout` with or without the sidebar; `state-card.tsx`, `query-states.tsx`: loading, offline and error states of a screen's queries; `offline-notice.tsx`; `text-field.tsx`: `TextField` and the six-digit `TotpField`) and `src/lib/`: `i18n.ts`; `error-logging.ts` (errors logged by name only); `api.ts` (the typed `openapi-fetch` client on the console's own origin, each request bound to the identity scope it was sent in; `unwrap` and `unwrapEmpty`, which turn a refusal into an `ApiError` carrying its code only; `watchSession`, which hears only refusals of the current identity's requests); `identity-scope.ts` (the signed-in user's scope: `signedIn`, `forgetSession` and `meQuery` move it, which stops the previous user's requests, mutations and the code awaiting them); `api-schema.gen.ts` (the API's types, generated from `apps/api/openapi.json` by `test/api-schema.test.ts`, committed, never edited or read); `error-text.ts` (a code's Arabic text; the end of a session and `REAUTH_REQUIRED` have the console's own); `query-client.ts` (on every change of identity: every query but the session's view, `meta: sessionMeta`, removed, the previous user's mutations dropped and their callbacks never run); `online.ts`; `format.ts` (dates and times in `Asia/Damascus` with Latin digits).
- The UI comes from `packages/ui` (ADR 0018), wired as in `apps/restaurant`: `src/styles.css`, `vertexFoodWeb()` in `vite.config.ts`, the shell as `AppLayout` with the sidebar's links, `ThemeToggle` and `PoweredBy`, the favicon from `brand/`. The console keeps the Vertex identity: no restaurant accent. `vite.config.ts` forwards `/api` to the local API in development (`API_PORT`, 3100 by default): the console and the API share one origin, as the host will serve them.
- Unit tests sit next to the code; `test/` holds the generated-client drift test; the logical-CSS and token rules are `packages/ui`'s convention test, which covers `src/`. `e2e/`: Playwright against `vite preview`, light and dark; the API is mocked in memory by `e2e/mock-api.ts` (the console routes, bodies validated with the contracts, the proof of work checked, single-use tickets, the session, the re-authentication window, the console limits, the self and last-admin rules; every authenticator shows `totpCode`). `mockConsoleApi(page, { signedIn })` starts with a session and tracks the page's requests: `e2e/settle.ts`'s `settled(page)` waits until no fetch is open and the layout is still, and `screenshot` calls it. `e2e/responsive.spec.ts` and `shell.spec.ts` check every screen at the `viewports` of `e2e/screenshot.ts`.
- Ports: dev 5274, `vite preview` 4274. The API's `CONSOLE_ORIGINS` defaults to the console's loopback dev origins outside production: writes from another origin are refused.

## Rules
- Every text through i18next with keys from `packages/i18n` (this app's namespace is `console`); never a literal in a component. Numbers and dates through `Intl` with `formatLocale` from `@vertex-food/i18n` (Latin digits); times shown in `Asia/Damascus` (`lib/format.ts`).
- Design-system components and tokens only, logical directions only, pinned by `packages/ui/src/conventions.test.ts`, as in `apps/restaurant`. A component the design system lacks is built here only when the app needs it; it moves to `packages/ui` with its second user.
- Every screen has its loading, empty, error and offline states (ADR 0020). An error state never shows or logs the error's message (ADR 0016); log errors with `logErrorLabel`.
- The console calls `/api/console/` routes, which declare `@ConsoleRoute(permission)`, and the public `/api/auth/pow` for the sign-in's proof of work; UI checks (`holds`) are cosmetic (ADR 0005).
- The session is the API's `HttpOnly` cookie: the page never stores a token, a ticket, a setup code or a recovery code (not in a URL, storage or TanStack's caches: `signedIn` drops the recovery codes, and a mutation whose answer holds one runs with `gcTime: 0`). A request answered `UNAUTHENTICATED` or `SESSION_ENDED` clears the query and mutation caches (`forgetSession`) and opens `/sign-in` (`?ended=true` when a session was running); signing out does the same, from the sign-out mutation's `onSuccess`. Callbacks go in `useMutation`'s options (never in `mutate`'s second argument), so a former user's answer never reaches the next user's screens.
- A sensitive action (spec S02 rule 40: platform users, tenant status and slug, owner recovery, phone changes) runs inside `useReauth()`: it asks for a TOTP when `me` says the 5-minute window is closed, and again on `REAUTH_REQUIRED`; cancelling fails the action with `REAUTH_REQUIRED`. A recovery-code sign-in leaves the window closed.
- Server state through TanStack Query (`query-client.ts`): offline, queries pause, saving is disabled and nothing is queued (mutations run with `networkMode: 'always'`). A refusal is shown by its code's text (`useErrorText`), never the server's message.
- A change to `apps/api/openapi.json` fails `test/api-schema.test.ts` until the types are regenerated: `pnpm --filter @vertex-food/console exec vitest run test/api-schema.test.ts -u`.
- No `X-Powered-By`; security headers (CSP and the rest) are set by the host at the first deploy.
- UI changes add or update the E2E RTL screenshots (light and dark) and are looked at before the PR. Every screen is checked at the `viewports` of `e2e/screenshot.ts` (phone, tablet both ways, desktop) for sideways scrolling and, below 1024 px, 44 px touch targets (measured once a dialog has finished growing in).

Run: `pnpm --filter @vertex-food/console test` · E2E: `pnpm verify apps/console/e2e/<file>.spec.ts` (builds first; `pnpm verify` runs the whole suite when the branch affects this app, and CI runs every suite, `docs/testing.md`) · dev: `pnpm --filter @vertex-food/console dev`.
