# apps/web

The public web (ADR 0015, layout ADR 0020): a Next.js App Router app, Arabic-first RTL (ADR 0018), for QR menus, restaurant pages on subdomains and custom domains, and the customer's web ordering. Copied from Vertex Shifa's site skeleton and adapted. Today it is the shell only: no API calls, tenant subdomains or custom domains yet (S15, S17).

## Layout
- `src/app/`: thin App Router files. `layout.tsx` and `global-error.tsx`, which replaces it, share `src/app/root-document.tsx`: `<html lang dir>` and `theme-init.js` (served by `src/app/theme-init.js/route.ts`); the layout sets the page title and favicon (metadata), the `DirectionProvider` and the shell; `page.tsx` files re-export a feature's screen; `not-found.tsx`, `error.tsx` and `global-error.tsx` are the not-found and error states.
- `src/features/<area>/`: the components and data of one area; the pattern to copy is `features/home/`. App-wide `src/components/` (shell, state card, states) and `src/lib/` (`i18n.ts`; `error-logging.ts`: errors logged by name only).
- `src/instrumentation.ts` (server) and `src/instrumentation-client.ts` (browser, before hydration) redact errors passed to `console.error`/`console.warn`.
- The UI comes from `packages/ui` (ADR 0018): `src/styles.css` imports Tailwind (`postcss.config.mjs`), `fonts.css` (`swap`: text never waits on a slow connection) and the design system's styles; `next.config.ts` lists `@vertex-food/ui` in `transpilePackages`. The shell has the mark, `ThemeToggle` and `PoweredBy`.
- Unit tests sit next to the code; the logical-CSS and token rules are `packages/ui`'s convention test, which covers `src/`. `e2e/`: Playwright against `next start`, light and dark.
- Ports: dev 5275, `next start` 4275. `next-env.d.ts` is generated by `next typegen`/`next build` and git-ignored.

## Rules
- Server components by default; `'use client'` only where Next.js or interaction needs it (error boundaries, later the cart).
- Every text through the i18next instance in `src/lib/i18n.ts` with keys from `packages/i18n` (this app's namespace is `web`), used directly (`i18n.t`, `i18n.getFixedT(null, 'web')`), not through `react-i18next`: server components have no React context. Never a literal in a component; the title comes from the catalog through `metadata`. Numbers and dates through `Intl` with `formatLocale` (Latin digits); times shown in `Asia/Damascus`.
- Design-system components and tokens only, logical directions only, pinned by `packages/ui/src/conventions.test.ts`, as in `apps/restaurant`.
- Every page has its loading, empty, error and offline states (ADR 0020). An error state never shows or logs the error's message: it may carry restaurant or customer data (ADR 0016). Log errors with `logErrorLabel`.
- Tenant-branded pages change identity and settings only, never CSS, HTML or logic (ADR 0010): the restaurant's accent through `tenantStyle(identity)` on the page's root and `bg-tenant-accent`, its logo and cover as images. They always show `PoweredBy` (ADR 0018). Prices and totals shown here are recomputed by the API at checkout (ADR 0007).
- No fonts or scripts from third-party hosts (`next/font/google` fetches at build time); no Cloudflare (ADR 0015, 0017).
- No `X-Powered-By`; security headers (CSP and the rest) are set by the host at the first deploy.
- UI changes add or update the E2E RTL screenshots (light and dark) and are looked at before the PR. Every page is checked at the `viewports` in `e2e/shell.spec.ts` (phone, tablet both ways, desktop) for sideways scrolling.

Run: `pnpm --filter @vertex-food/web test` · E2E (after `build`): `pnpm --filter @vertex-food/web test:e2e` · dev: `pnpm --filter @vertex-food/web dev`.
