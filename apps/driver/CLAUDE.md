# apps/driver

Vertex Food Driver, for restaurant and Vertex drivers (ADR 0003, 0009, 0024, layout ADR 0020): React Native + Expo (SDK 58, managed workflow, prebuild when a native module needs it) with Expo Router, Android first, Arabic-first RTL (ADR 0018). Copied from `apps/customer`. Today it is the shell only. S19 brings duty, jobs, the foreground-service tracker, the SQLite queue with its time base and the outcomes screen (ADR 0024).

## Layout
- `app.config.ts`: the app name from the catalog (`driver.appName`), `orientation: 'default'` (phones and tablets both ways, owner 2026-10-20), Android and web (the static web export, for the E2E only, never hosted), RTL forced natively (`extra.forcesRTL`), the sitemap route off. Store identifiers, the EAS project and icons arrive with the first store build (Q3); the icon is `brand/logo/png/driver-app-icon-1024.png` (green mark on sand, identity §11). `android/` is generated by prebuild and git-ignored.
- `src/app/` (with `+html.tsx`), `src/features/<area>/`, `src/components/`, `src/lib/`, `e2e/` (web server on `127.0.0.1:4277`, every screen at the `viewports` in `e2e/shell.spec.ts`): as in `apps/customer`; the pattern to copy is `features/home/`. The shell adds the product label from `driver:productLabel`.
- `pnpm build` is `expo export` for Android and web (the JavaScript bundle and the static web export, into `dist/`); native builds run on EAS Build or a CI runner outside Syria, because Google's SDK downloads fail from there (ADR 0024). Dev server: 5277.

## Rules
- Every text through i18next with keys from `packages/i18n` (this app's namespace is `driver`); never a literal in a component. Syrian month names and Latin digits through `formatLocale` (Hermes unverified until the first development build, as in `apps/customer`); times shown in `Asia/Damascus`.
- Logical style properties only, pinned by `packages/ui-native/test/conventions.test.ts`; colors and sizes through `useTheme()` from `@vertex-food/ui-native`; as in `apps/customer`. The driver app keeps the Vertex identity: no restaurant accent (ADR 0010).
- Location only while on duty, through a foreground service the driver starts from the screen; no background location permission; `RECEIVE_BOOT_COMPLETED` declared with `expo-location` (ADR 0024). A driver sees customer details only while the job is active (ADR 0009).
- Customer phones, addresses and driver locations travel only in request and response bodies, never in URLs or logs (ADR 0006, 0016). Requests use a native timeout, never `fetch` with a JavaScript timer (ADR 0024).
- Every screen has its loading, empty, error and offline states (ADR 0020); queued job events and their outcomes are always visible, never dropped silently (ADR 0024). An error state never shows or logs the error's message; log errors with `logErrorLabel`.
- Versions of Expo packages come from `pnpm exec expo install <package>`, pinned exactly; ADR 0024 lists the S19 additions. On each SDK upgrade, recheck `src/lib/native-error-reports.ts` (React Native's internal `ExceptionsManager`), as in `apps/customer`; `native-error-reports.test.ts` fails until it is.
- UI changes add or update the E2E RTL screenshots (light and dark) and are looked at before the PR; location, the foreground service and native behaviour need a development build on a real phone (Q19), which a session cannot run: the report lists those checks under "Needs from you".

Run: `pnpm --filter @vertex-food/driver test` · build: `pnpm --filter @vertex-food/driver build` · E2E: `pnpm verify apps/driver/e2e/<file>.spec.ts` (builds first; `pnpm verify` runs the whole suite when the branch affects this app, and CI runs every suite, `docs/testing.md`) · dev: `pnpm --filter @vertex-food/driver dev`.
